# Notwehr & Notstand — интерактивный урок

Самостоятельный сайт на React + TypeScript + Vite, обычный CSS с design tokens.
Без backend, аналитики, AI API и сторонних плееров. Интерфейс — на немецком.

**Готово сейчас:**
1. Вступление и эпизод «Empfang» (Verstehen, Notwehr § 227 BGB): видео → стоп-кадр →
   разбор двух деталей → одно закрепление → переход дальше.
2. Эпизод «Dachpfannen» (Unterscheiden, § 228 BGB): видео → продолжение и учебный вопрос →
   сопоставление «источник опасности / повреждённая вещь» → правило и последствия.
3. Эпизод «Verschlossene Tür» (Unterscheiden, § 904 BGB): видео → обстоятельства и выбор действия →
   ролик ветки → учебный вопрос о роли двери → § 904 → сравнение норм.
4. Короткий экран «Ein Vorfall – zwei rechtliche Perspektiven» (§ 32 StGB / § 227 BGB), не тест.
5. Заключительный видеокейс «Ein Vorfall am Eingang» (`dog-bottle.mp4`): текстовое продолжение и
   условия → Selbstcheck, 5 заданий по очереди → «Ihr Ergebnis» (X von 7) → повтор только ошибок.

Временное завершение после двери удалено. Конвейер (`machine.mp4`) исключён. Время
прохождения всего урока не измерялось: «около 5 минут» — по-прежнему только оценка.
Полный план — в [docs/storyboard.md](docs/storyboard.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5195
npm test           # тесты машин состояний (vitest)
npm run build      # проверка типов + production build в dist/
npm run preview    # раздача dist/ на http://localhost:4195
```

`dist/` собирается с относительным `base: './'` (см. `vite.config.ts`), поэтому его
можно положить в любую подпапку статического хостинга. Автоматически сайт никуда не
публикуется.

## Структура

```
src/
  content/types.ts          типы контента и медиа
  content/lesson.ts         тексты, медиа, хотспоты, ветки, правовые источники
  state/segmentMachine.ts   видео-состояния и эпизод «Empfang»
  state/episodeMachines.ts  шаги панелей «Dachpfannen» и «Tür»
  state/finalMachine.ts     итоговая проверка: первая попытка, блокировка, письменная часть, повтор ошибок
  content/finalCheck.ts     экран перспектив, финальный кейс, 5 заданий, 7 решений, письменная часть, результат
  state/*.test.ts           тесты: пауза, повторный ended/seek, replay, двойные клики, ветки
  components/
    CourseShell             шапка, порядок эпизодов, фокус на заголовок
    ReceptionEpisode        вступление + эпизод «Empfang»
    RoofEpisode             эпизод «Dachpfannen»
    DoorEpisode             эпизод «Tür»
    SituationScreen         раскладка видео + панели, одно движение 300 ms
    VideoScene              плеер, остановка по времени, стоп-кадр, текстовая альтернатива
    BranchVideo             будущий ролик ветки: проверка загрузки, запасной текст
    HotspotScene            маркеры и выделения на стоп-кадре (учитывает поля object-fit: contain)
    ExplanationPanel, DecisionCheck   панели эпизода «Empfang»
    ChoiceGroup             компактный выбор (нативные radio) + обратная связь
    PerspectivesIntro       экран «zwei rechtliche Perspektiven»
    FinalCheckFlow          финал: кейс → задания → результат → повтор
    CaseTask                видеокейс и задание 1: хотспоты, фиксация ответов, письменная часть, результаты
    TaskScreen              задания 2–5 и экраны повтора
    DecisionOutcome         проверенное решение: статус словами и иконкой, ответ, пояснение
    FinalResult             результат, памятка, Rechtsquellen, «Neu starten» с подтверждением
    MobilePreview           «Mobile Vorschau» на десктопе: то же приложение в iframe 390 × 844
  styles/tokens.css, styles/app.css
public/media/               видео и кадры
```

Видео-состояния: `ready → playing ⇄ paused → analysis`, отдельно статус медиа
`loading / ready / error`. Пауза пользователя не открывает разбор. Остановка ловится
по `requestVideoFrameCallback` с запасным `timeupdate`, без `setTimeout`. Каждый шаг
панели принимает только своё событие, поэтому повторный клик не перескакивает дальше.

## Видео и кадры

| Файл | Длительность / формат | Стоп-кадр | Примечание |
|---|---|---|---|
| `reception.mp4` | 10 с, 1920×1080, есть аудио | 4,5 с | копия `publicmediareception.mp4` |
| `roof-tiles.mp4` | 5 с, 1920×1080, есть аудио | 4,8 с | копия `roof-tiles.mp4` из корня проекта |
| `door-start.mp4` | 5 с, 1920×1080, есть аудио | 4,8 с | копия `door-start.mp4` из корня проекта |
| `door-open.mp4` | 5 с, 1920×1080 | конец ролика | ветка «Tür beschädigen», **старт с 3,6 с** (`startAt`) |
| `door-wait.mp4` | 5 с, 1920×1080 | конец ролика | ветка «Warten», целиком |

Все ролики (кроме первого) лежали в корне проекта, а не в `public/media/`.
Я скопировал их туда, оригиналы не тронуты. Постеры (`*-poster.jpg`, кадр 0,3–0,5 с) и
стоп-кадры (`*-freeze.jpg`) экспортированы через `<video>` + `<canvas>` в браузере
(ffmpeg в системе нет) на тех же отметках, что `pauseAtSeconds`.

**Заменить видео:** положите файл в `public/media/` и поменяйте `src` в соответствующем
`…Media` в `src/content/lesson.ts`.

**Поменять момент остановки:** `pauseAtSeconds`. После изменения заново экспортируйте
`*-freeze.jpg` на тот же момент, иначе будет скачок. Если стоп-кадра нет, сайт
останавливает само видео на `pauseAtSeconds`.

**Координаты:** `hotspots[].marker` / `hotspots[].region` (Empfang) и `compare.region`
(Dachpfannen) — относительные 0..1 от исходного кадра. Например, x = 690 / 1920 ≈ 0.36.

### Видео веток двери

В `doorEpisode.branches[].video` в `src/content/lesson.ts`:

```ts
video: { src: media('door-open.mp4'), available: true, startAt: 3.6 },
video: { src: media('door-wait.mp4'), available: true },
```

- После «Entscheidung ansehen» ролик выбранной ветки сразу запускается без звука в блоке
  исходной сцены. Это действие пользователя; если браузер всё равно блокирует запуск,
  появляется кнопка воспроизведения. Варианты выбора скрыты, объяснения нет до конца ролика.
- После окончания остаётся финальный кадр, а в панели — обратная связь именно этой ветки и
  кнопки «Weiter» (к § 904), «Video erneut ansehen», «Andere Entscheidung ansehen» /
  «Zurück zu Ihrer Entscheidung». Первоначальный выбор хранится отдельно от просматриваемой ветки.
- На странице всегда только один ролик: исходная сцена и ролик ветки не монтируются одновременно.
- «Als Text lesen» или ошибка загрузки/воспроизведения → текстовое продолжение ветки
  с той же обратной связью. Если ролик не загрузился, кнопка повтора у этой ветки скрыта.
- **`startAt` у `door-open.mp4`:** примерно с 1,5 до 3,3 с открытие выглядит неестественно
  (рука на стекле, странный предмет у края двери, «призрачная» створка). С 3,6 с дверь уже
  открыта, человек выходит из комнаты. Остаётся около 1,4 с ролика; если этого мало, уменьшите
  `startAt` (например, до 3,3 с) или уберите его. Оригинальный файл не изменён.
- Подпись «Sie öffnen die Tür unter Beschädigung des Schlossbereichs» показывается только в
  текстовом режиме. Под роликом её нет: видео не показывает, как именно повреждена дверь.
- Кнопка панели § 904 теперь называется «Zur Übersicht», чтобы две кнопки «Weiter» не шли
  подряд и быстрый двойной клик не проскакивал объяснение.

### Переключатели для разработчика

Обучающемуся они не показываются.

- `?start=roof` / `?start=door` / `?start=final` — открыть часть сразу.
- `?media=missing` — подменить все основные ролики и кадры несуществующими путями.
- `?preview=mobile` — ставится самой рамкой предпросмотра, кнопка внутри не показывается.
- `?branches=missing` — подменить ролики веток несуществующими путями (проверка запасного текста).

## Что видно в реальных роликах

- **Empfang:** см. итерацию 1 — три человека в кадре, кулак поднят и удерживается.
- **Dachpfannen:** камера почти статична. Несколько сдвинутых черепиц в верхней части крыши
  видны всё время. Охранник стоит на тротуаре и смотрит вверх, рядом машина.
  Текстовая альтернатива из ТЗ совпадает с кадром; я добавил, что сотрудник смотрит на черепицу.
- **Tür:** охранник примерно 1,5 с пробует ручку, потом отпускает. Человек за стеклом
  поднимает ладонь к стеклу и выглядит спокойным. **Дым едва заметен** (лёгкие струйки
  вверху), поэтому в текстовой альтернативе вместо «verrauchter Raum» написано «Im Raum
  ist leichter Rauch zu erkennen». Острая опасность задаётся условием «Für diesen Fall gilt».
- На всех трёх роликах есть водяной знак «KlingAI 4.0» и аудиодорожка. Звук я не слышал:
  видео стартуют без звука, звук включается кнопкой «Ton ein». Если в роликах есть речь,
  нужны субтитры.

## Пункты для fachliche Freigabe

1. Empfang: жест (поднятый кулак без начатого удара) и охранник в кадре — оставлено как
   есть по решению заказчика.
2. Tür: в ролике мало дыма, а человек выглядит спокойным. Сейчас «akute Lebensgefahr»
   держится только на условиях. Возможно, стоит переснять сцену.
3. Erforderlichkeit/Gebotenheit в Notwehr только названы. Нужно решить, хватает ли этого
   для задания 9.
4. Итог § 228 сформулирован так: «Nach § 228 BGB ist zum Schadensersatz verpflichtet, wer
   die Gefahr selbst verschuldet hat». Другие основания ответственности здесь сознательно
   не рассматриваются.

## Итоговая проверка (финальный кейс)

**Ролик `dog-bottle.mp4`** (лежал в корне проекта, скопирован в `public/media/`): 5 с, 1920×1080,
есть аудиодорожка. Примерно с 1,5 до 3 с собака скалит зубы и идёт на охранника, справа стоит
гость с зелёной стеклянной бутылкой; к 4 с собака успокаивается. Стоп-кадр — **2,6 с**
(`dog-freeze.jpg`), постер — 0,3 с. Удар, травма и смерть собаки не показываются; что бутылка
разбилась, нигде не утверждается.

**Хотспоты** (`caseHotspots` в `src/content/finalCheck.ts`, относительные координаты кадра):
собака — маркер на плече (x 0.27, y 0.66), бутылка — x 0.815, y 0.585. Рядом дублирующие кнопки
«Einwirkung auf den Hund» / «Verwendung der Glasflasche». Если стоп-кадра нет, остаются только кнопки.

**Проверка положений до финала:** Notwehr/Nothilfe — Empfang; § 228, своя вина и § 90a — Dachpfannen;
§ 904 и возмещение — Tür; разные критерии — в обоих эпизодах. Не хватало только сравнения
BGB/StGB — для него добавлен экран перед кейсом.

**Оценка:** ровно 7 решений — `dog_basis`, `bottle_basis`, `defensive_conditions`,
`aggressive_conditions`, `compensation`, `notwehr_basis`, `legal_perspectives`. Правильность
сравнивается только по стабильным ID вариантов (`correct` в `finalCheck.ts`), не по позиции.
Перемешивания нет. Сохранения прогресса тоже нет (состояние живёт только в памяти страницы),
поэтому старые результаты из 8 решений появиться не могут и версия данных не нужна.

Первый ответ фиксируется только при отправке задания и после этого заблокирован; повторный клик
ничего не меняет. «Zurück» показывает уже проверенные задания без сброса. Повтор ошибок
(«Unsichere Entscheidungen noch einmal ansehen») спрашивает только ошибочные решения, с картинкой/описанием кейса,
и не меняет результат первой попытки; после неё на экране результата появляется «Wiederholung abgeschlossen».
Проходного процента нет. «Neu starten» открывает подтверждение с выбором:
«Nur die Abschlussprüfung» (кейс и задания заново) или «Die gesamte Lerneinheit» (всё с вступления,
все эпизоды со свежим состоянием); «Abbrechen» ничего не меняет.

**Письменная часть (внутри задания 1, не шестое задание).** «Zuordnung übernehmen» фиксирует оба
ответа без показа правильности → «Begründen Sie Ihre Zuordnung» → «Mit Musterlösung vergleichen»
(нужен непустой текст после trim, ключевые слова и длина не проверяются) или «Ich bin unsicher –
Musterlösung ansehen» → результаты, собственный ответ, образец и два необязательных пункта
самопроверки. Текст и отметки хранятся только в состоянии страницы: они не оцениваются и никуда
не отправляются. В повторе ошибок письменной части нет.

**Уточнения до Selbstcheck.** Блок Notwehr (панель эпизода «Empfang») дополнен текстом о человеческом
нападении, Nothilfe и животных. Сравнение §§ 228/904 у двери теперь отдельное состояние панели
«Im Vergleich» (кнопка «Zum Vergleich» после § 904): там термин Verhältnismäßigkeit, критерии обеих
норм и отдельная строка про § 227.

**Длина вариантов.** В 2b, 4 и 5 неверные варианты дополнены без изменения смысла, чтобы верный
не выделялся длиной. При правке текстов сверяйте длины: верный вариант не должен быть заметно
длиннее или короче остальных.

Кнопка на экране § 904 переименована в «Nächster Abschnitt»: после неё идёт экран перспектив.

## Обучающие сцены: сначала решение, потом вывод

- **Принцип:** до решения показываются только факты и вопрос; квалификация, объяснение и сравнение
  идут после ответа.
- **Учебные вопросы** (Empfang, Dachpfannen, Tür) живут в `segmentMachine` и `episodeMachines` и не
  связаны с `finalMachine`, поэтому на итоговый балл не влияют.
- **Tür:** выводы о необходимости и о роли двери убраны из условий и из обратной связи веток. Они
  появляются после вопроса «Welche Rolle spielt die Tür…». Панель § 904 сокращена (без пункта «Ziel»).
- **Dachpfannen:** последовательное раскрытие заменено одним вопросом; рамка и названия нормы
  появляются после ответа. В эпизоде и в сравнении используется один термин: «Dachpfannen».
- **Empfang:** новый вопрос без формулировки «zur Strafe». Блок Notwehr ужат без потери фактов.
- **Verhältnismäßigkeit:** новое вводное определение в панели «Im Vergleich», до Selbstcheck.
- **«Mehr erfahren»** не добавлялся: всё оставшееся нужно для ответов в основном маршруте.

**Расхождение с роликом:** в условии двери сказано «dichter Rauch», а в `door-start.mp4` дыма мало. Условие
стоит под заголовком «Für diesen Fall gilt:», а текстовая альтернатива описывает видео («leichter Rauch»).

### Что проверено (обучающие сцены)

- `npm test`: 19 тестов; `npm run build` без ошибок.
- В браузере: весь маршрут от вступления до результата. До ответа в панелях двери и черепицы нет §,
  названий норм и выводов, на кадре черепицы нет рамки. Неверные ответы на учебные вопросы не изменили
  итог: 5 из 7 при двух ошибках в самом Selbstcheck, всего 7 решений в 5 заданиях, повтор показывает
  только их. Ролики обеих веток с объяснением только после конца. Клавиатура в обоих новых вопросах.
- Mobile 390×844: панели от 350 до 785 px, горизонтального скролла нет.
- Не проверено: время прохождения (не измерялось), Safari/Firefox, экранный диктор, reduced motion.

## Мобильная версия и «Mobile Vorschau»

- **Прогресс:** этапы теперь видны и на телефоне, второй строкой шапки (раньше они были скрыты).
- **Hotspots на узких экранах:** кнопки и пояснение идут сразу под кадром, условие и резюме ниже; у пояснения и
  у кнопок заданий тот же номер, что на маркере; при нажатии маркера кадр и текст попадают на экран вместе.
  На десктопе порядок и вид не менялись.
- **Экранная клавиатура:** `interactive-widget=resizes-content`, при вводе шапка не закреплена, поле с кнопкой
  под ним прокручиваются в видимую область.
- **Предпросмотр:** кнопка в шапке только при `min-width: 1024px`, `hover: hover`, `pointer: fine`. Рамка 390 × 844 px,
  но не больше окна (фактический размер подписан в заголовке). Это отдельный документ в iframe со своим
  состоянием в памяти, поэтому основной урок не меняется; при открытии его видео встаёт на паузу. При закрытии
  рамка уничтожается. Escape внутри рамки передаётся родителю через `postMessage`, фокус возвращается на кнопку.

### Что проверено (мобильная версия)

- `npm test`: 21 тест; `npm run build` без ошибок.
- Эмуляция в браузере 360×740, 390×844, 430×932: весь маршрут скриптом, на каждом шаге поиск горизонтального
  переполнения, обрезанных элементов, целей нажатия меньше 44 px и скрытого прогресса — проблем нет. На 390 px с
  реальными роликами, обе ветки двери до конца. Hotspots 48×48; на 390×844 кадр и пояснение видны одновременно.
- Клавиатура: только имитация уменьшенным окном 390×450 — поле и кнопка «Mit Musterlösung» видны вместе.
- На 1440×900: предпросмотр (ширина 390, мобильные media queries, видео, hotspots), изоляция, закрытие кнопкой,
  Escape снаружи и изнутри рамки, возврат фокуса, чистое повторное открытие. Основной маршрут до 7 von 7 на production-сборке.
- Не проверено: реальный телефон и настоящая экранная клавиатура, скрытие кнопки при `pointer: coarse` на реальном
  устройстве, Safari/Firefox, экранный диктор, время прохождения (длительность не заявляется).
